# Flag Guesser

Flag Guesser is a tiny two-player flag guessing duel. One player mints a private link, tweaks the number of rounds and seconds per flag, and shares the URL (the hash at the end identifies the session). A second player opens the link, the server streams flag emojis, and both race to guess the country. Sessions live only in memory—close the tab or stop the server and everything disappears.

## Features

- ⚡️ Websocket-powered 1v1 matches with a synchronized countdown per flag
- ✂️ Ephemeral rooms with no persistence or analytics
- 🔗 Hash-based private invites—share a URL, no codes required
- 🪪 Auto-generated nicknames—no logins, accounts, or manual entry
- 🧮 Time-based scoring backed by fuzzy name matching
- 🧰 TypeScript codebase with modular services and Vitest coverage
- 🌍 Flag lookup sourced from the public [annexare/Countries](https://github.com/annexare/Countries) dataset

## Prerequisites

- Node.js 18 or newer (Node 22 recommended)
- npm 9+

## Getting Started Locally

1. Install dependencies:
   ```bash
   npm install
   ```
2. Fetch the latest emoji/name lookup (requires `curl`, only needed the first time or when refreshing data):
   ```bash
   npm run download-flags
   ```
3. Build the TypeScript sources for both the server and client:
   ```bash
   npm run build
   ```
4. Start the compiled server:
   ```bash
   npm start
   ```
5. Open [http://localhost:3000](http://localhost:3000) in two browser tabs or devices.
   - The host selects rounds and time limit, then creates a room.
   - Share the invite link (e.g. `http://localhost:3000/#ABC123`) with your opponent.

For hot reloading during development, run the TypeScript entrypoint directly:
```bash
npm run dev
```
This launches an auto-reloading server powered by `tsx`. Re-run `npm run build` before `npm start` to refresh the compiled output.

## Deployment on a Fixed-Price VM

Because the server is a single Node.js process with in-memory rooms, deployment on a budget VPS is straightforward:

1. Provision an Ubuntu/Debian VM (1 vCPU / 1 GB RAM is sufficient).
2. Install Node.js (via apt or `nvm`) and clone/pull this repository.
3. Run the setup steps above (`npm install`, `npm run download-flags`, `npm run build`).
4. Keep the server alive with a process manager:
   ```bash
   npm install -g pm2
   pm2 start dist/server/index.js --name flag-guesser
   pm2 save
   ```
   or create a `systemd` service that executes `node /path/to/dist/server/index.js`.
5. Expose port 3000 via your firewall or reverse proxy. Tools like Nginx or Caddy can terminate HTTPS and forward traffic to the Node process.

The game stores no state outside memory. Restarting the process immediately clears any in-progress rooms, satisfying the ephemeral session requirement.

## Refreshing Flag Data

The `data/flags.json` file is generated by `npm run download-flags`. The script shells out to `curl` to pull emoji and name tables from the annexare dataset, merges them, and saves a JSON payload used by both the server and tests. Commit the file if you regenerate it so tests remain deterministic.
